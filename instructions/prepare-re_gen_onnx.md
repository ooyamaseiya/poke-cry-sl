# 実装指示書：ポケモン鳴き声推定モデル（実データ取得・教師あり学習 → ONNX生成）

## 1. プロジェクトの目的

アーケードゲーム（ポケモンフレンダ等）の騒音環境下において、録音した鳴き声（WAV / OGG）から隠れているポケモンの種類（上位候補 Top-3）を推定する音声分類モデルを構築し、単一ファイルの推論用モデル `models/pokemon_model.onnx` を生成する。

※ 強化学習（RL）は使用せず、対象ポケモン＋「その他（雑音）」を1つのモデルで同時に分類する**教師ありマルチクラス分類（ディープラーニング）**で実装すること。
※ テスト用のダミー音声（サイン波）での学習は禁止し、必ず**本物のポケモン鳴き声データ**を取得して学習・検証を行うこと。

---

## 2. 技術スタック・環境制約

- **言語・FW:** Python 3.12+ / PyTorch（CPU環境での学習を前提に軽量設計にすること）
- **音声処理:** `soundfile`, `librosa`, `numpy`（※Python 3.13非互換の `pydub` は使用しないこと。`.wav`, `.ogg`, `.mp3`, `.flac` の読み込みに対応すること）
- **ONNX関連:** `onnx`, `onnxruntime`
- **基本方針（処理の完全共通化）:**
  - 学習時と推論時（CLIテストおよびWebアプリ）の計算ズレを完全に防ぐため、音声前処理およびログメルスペクトログラム変換は **`src/audio_processor.py` の `AudioProcessor` クラスに一元化** し、全スクリプトから必ずこのクラスをインポートして使用すること。

## 4. 実データ取得スクリプトの仕様（`src/setup_real_data.py`）

ダミーデータによる誤学習を防ぐため、以下の処理を行うセットアップスクリプトを実装すること。

1. **既存ダミーデータのクリーンアップ:**
   - `data/raw/` 配下に過去のダミーファイル（`000.wav` 〜 `004.wav` 等）が残っている場合は削除すること（ユーザーが手動配置した実データファイルは消さないこと）。
2. **本物のポケモン鳴き声のダウンロード:**
   - PokeAPI の公開リポジトリ（`https://raw.githubusercontent.com/PokeAPI/cries/main/cries/pokemon/{variant}/{dex_id}.ogg`）から、`latest` と `legacy` の両方の `.ogg` ファイルをダウンロードし、`data/raw/{NN}_{pokemon_name}/` に保存すること。
   - コマンドライン引数で `図鑑番号:英語名`（例: `python -m src.setup_real_data 384:rayquaza 25:pikachu 6:charizard 150:mewtwo`）を受け取れるようにし、引数省略時のデフォルトは少なくとも `384:rayquaza`, `25:pikachu`, `6:charizard`, `150:mewtwo` の4種類を取得すること。
3. **背景クラス（`00_other`）と拡張用ノイズ（`data/noise`）の生成:**
   - `data/raw/00_other/` に、多様な非ポケモン音（ホワイトノイズ、低域の空調・筐体ファン風ノイズ、60Hz/120Hzハム音、高周波ビープ音、ほぼ無音、話し声帯域の変調ノイズなど最低6パターン以上）を生成して保存すること。
   - `data/noise/` に、データ拡張合成用の複数パターンの環境ノイズ（各5秒）を生成して保存すること。

## 5. 音声前処理・音響特徴量の仕様（`src/config.py`, `src/audio_processor.py`）

学習・検証・推論・Webアプリのすべてで完全に同一の数値が出力されるよう実装すること。

1. **音声読み込み・基本整形**
   - 対応形式: `.wav`, `.ogg`, `.mp3`, `.flac`（メモリ上の `bytes` およびファイルパスの両方から `16000 Hz` モノラル波形を読み込めること）。
   - 無音トリミング: `librosa.effects.trim(top_db=30)` で発音区間を検出し、元波形から前後 `0.15秒`（2,400サンプル）の余白を残して切り出す。
   - 固定長統一: **`2.5秒`（40,000サンプル）** に揃える。
     - 2.5秒未満の場合：後ろにゼロパディング（無音追加）。
     - 2.5秒超過の場合：振幅（絶対値）が最大のピーク位置を中心に2.5秒分を切り出す（先頭切り出しは禁止）。
   - 音量正規化: ピーク振幅が `1.0` になるよう正規化（無音の場合はゼロのまま）。

2. **ログメルスペクトログラム変換**
   - `SAMPLE_RATE = 16000`, `N_FFT = 1024`, `HOP_LENGTH = 160`, `N_MELS = 64`, `F_MIN = 50.0`, `F_MAX = 8000.0`
   - パワースペクトログラムをデシベル変換（`librosa.power_to_db(ref=np.max)`）した後、**サンプル単位の標準化 `(S_db - mean) / (std + 1e-8)`（平均0・標準偏差1）を必ず適用する**こと。
   - モデル入力テンソル形状: `[Batch, 1, 64, 251]`（`float32`）に厳密に固定すること。

## 6. データ分割・データ拡張の仕様（`src/prepare_data.py`）

1. **クラスごとの安全な Train / Val 分割:**
   - 全クラスを一括でランダム分割するのではなく、**クラスごとに原音ファイル単位で分割**すること。
   - 原音ファイルが3件以上のクラスは `Train 80% / Val 20%` で分割。
   - PokeAPIのように原音が **1〜2ファイルしかないクラス** は、まず水増し（1原音あたり50パターン生成）を行ってから、各原音由来のデータを `Train 80%（40件） / Val 20%（10件）` に分割し、学習データから特定のポケモンが欠落するのを防ぐこと。

2. **データ拡張（水増し）のルール:**
   - **クリーン原音の保持:** 騒音なしの綺麗な音声（`.ogg` 直入力等）でも高い確信度を出せるよう、ノイズを混ぜないクリーン原音（軽微な時間シフトのみ）も学習データに必ず含めること。
   - **時間軸シフト（ゼロパディング方式）:** `np.roll`（音声の末尾が先頭に回り込むループ現象）は使用せず、最大 `±0.2秒` の平行移動を行い、はみ出た端はゼロで埋めること。
   - **音量変動:** `0.6倍 〜 1.2倍` のランダムゲイン適用後に再正規化。
   - **背景ノイズ合成:** `data/noise/` のノイズからランダムな区間を切り出し、**SNR 0dB 〜 20dB** の範囲で合成。
   - **SpecAugment（Trainのみ適用）:** 時間マスク（最大20フレーム）と周波数マスク（最大8ビン）をランダムに適用。

3. **検証データ（Val）の品質担保（重要）:**
   - 同じクリーン画像を単に複数回コピーするだけの手抜き水増しは**禁止**する（1エポック目で正解率100%になり未熟なモデルが選ばれるのを防ぐため）。
   - 検証データにも固定の乱数シードを用いて、軽度〜中程度のノイズ（SNR 5dB 〜 20dB）や時間シフトを付与した**多様な評価用サンプル**を生成すること。

## 7. モデル学習・ONNX出力の仕様（`src/train.py`）

- **モデル構造:** CPUで高速に学習できる軽量2D CNN（Conv2d + BatchNorm2d + ReLU + MaxPool2d を4層重ね、Global Average Pooling + Dropout(0.3) + Linear でクラス数分を出力）。
- **学習設定:**
  - 損失関数: `nn.CrossEntropyLoss()`
  - 最適化: `torch.optim.AdamW(lr=1e-3, weight_decay=1e-4)`
  - エポック数: `30`（検証データ `Val` の正解率が最高になった時点の重みを保存。同率最高の場合はより後のエポックを採用すること）
- **単一ファイルONNXの出力:**
  - `model.eval()` 状態で `models/pokemon_model.onnx` にエクスポートすること。
  - PyTorchの仕様により `pokemon_model.onnx.data` という外部データファイルに分離された場合は、`onnx.load(..., load_external_data=True)` と `onnx.save_model(..., save_as_external_data=False)` を用いて**必ず単一の `.onnx` ファイルに統合**し、`.data` ファイルは削除すること。
  - 入力名: `["spectrogram"]`（形状: `[batch_size, 1, 64, 251]`、float32）、出力名: `["logits"]`（形状: `[batch_size, num_classes]`、float32）。
  - あわせて `models/labels.json` と `models/config.json` を出力すること。

## 8. 推論テストと完了条件

1. `src/setup_real_data.py` を実行し、ダミーデータを削除して本物のポケモン鳴き声（`.ogg`）と背景音データを配置すること。
2. `src/prepare_data.py` → `src/train.py` を実行し、エラーなく学習が完了して単一ファイルの `models/pokemon_model.onnx` が生成されること（学習ログで `Train Acc` と `Val Acc` が順調に上昇していることを確認すること）。
3. `src/predict_onnx.py` で `data/raw/01_rayquaza/384_latest.ogg` および `384_legacy.ogg` の両方を推論し、**どちらも `01_rayquaza` が第1候補（確率80%以上目安）として正しく判定されること**を確認して完了とする。
